My JSX standard (always, no exceptions)

  • 1
    Every arrow function: braces + return. items.map((item) => { return <li key={item.id}>…</li>; })
  • 2
    Decisions happen above the return with plain if, stored in variables. No && or ? : in JSX. let empty = null; if (list.length === 0) { empty = <p>None</p>; }
  • 3
    Skip inside a map: if (!items) return null;
  • 4
    Class names built above: let cls = 'row'; if (active) cls += ' is-active';
  • 5
    Handlers: named function above, arrow in JSX. onClick={() => { handleSelect(id); }}
  • 6
    Inputs: value + onChange, always. onChange={(e) => { setQuery(e.target.value); }}
  • 7
    Inside JSX only: tags, text, {variable}. Any JS → { }. No if / const / semicolons.

Component order

state → derived → handlers → decisions → JSX

export default function List({ items, activeId, onSelect }) {
  // 1. state

  // 2. derived data (filter, sort, group)

  // 3. handlers
  function handleSelect(id) { onSelect(id); }

  // 4. decisions (if → variables)
  let emptyMessage = null;
  if (items.length === 0) {
    emptyMessage = <p>Nothing here.</p>;
  }

  // 5. JSX: only tags, text, {variables}
  return (
    <div>
      {emptyMessage}
      <ul>
        {items.map((item) => {
          let rowClass = 'row';
          if (item.id === activeId) rowClass += ' is-active';
          return (
            <li key={item.id} className={rowClass}>
              <button onClick={() => { handleSelect(item.id); }}>{item.title}</button>
            </li>
          );
        })}
      </ul>
    </div>
  );
}

Plan any feature in 5 steps

  • 1
    Draw boxes on the design. Anything that repeats (a row, a card) is its own box. Name them. "A list, a repeating row, a detail panel."
  • 2
    Build it without interaction. Real data on screen, no clicking or typing yet. Hardcode what changes. "Static first, so I know the layout works."
  • 3
    List what can change. Cross off what never changes, what's passed in, and what you can work out from something else. What's left is state, usually 2–3 things. "The list and the selected id change; the count I calculate."
  • 4
    Decide where each changing thing lives. In the nearest box that contains every box that needs it. Used by one box only? Keep it there. "Both need the selected id, so it goes in the parent."
  • 5
    Let children report back. The owner passes down onSelect; the child calls it; only the owner changes state. "The row calls onSelect(id), the parent updates."

Boxes → static → what changes → where it lives → report back.

When stuck or blank

  • 1
    Say: "Let me step back. What state do I need, and what should be on screen?" Then do the smallest next step, even if it's hardcoding one row.
  • 2
    Read the first line of the error and the file/line it names.
  • 3
    console.log('visible', visible) right before the return, then open the Console tab. Is it the shape I think it is?
  • 4
    Where to log: above the return (best). Inside a map: switch => ( to => {, log, then return <li/>. In JSX: {console.log(x)} renders nothing, so it's safe.
  • 5
    Still lost? Comment out half the new code and see which half breaks.
  • 6
    Order of work: render it → make it work → empty/loading states → style. Say it out loud at the start.

Mistakes I keep making

  • 1
    map vs filter. Keeping some items? filter. map with a true/false return gives [true, false…].
  • 2
    A derived value is a plain value, recalculated every render. Don't call it, don't put it in state, don't pass it to onChange. If it's stale, its source isn't state.
  • 3
    Pass, don't call: onClick={save} or onClick={() => remove(id)}, never onClick={remove(id)}.
  • 4
    Every input gets value + onChange. Checkbox: checked + e.target.checked. Otherwise reset/clear won't show on screen.
  • 5
    Key on everything I map, including <option key={t}>. Stable id, not index.
  • 6
    Braces after => need return. x => { <li/> } returns nothing.
  • 7
    State is a snapshot. After setX(v), x is still old on this line. Use v.
  • 8
    Never mutate: no push, sort, obj.x = on state. Spread / map / filter, and [...arr].sort().
  • 9
    {n && …} prints 0. Write {n > 0 && …}.
  • 10
    Lists start as [], never undefined. Inputs give strings: Number(e.target.value).
  • 11
    In a form: e.preventDefault() first; other buttons need type="button".
  • 12
    Imports: export default → no braces. Named → braces, exact name.

Props wiring (the panic mistakes)

Two ends, different braces

passing = like HTML attributes · receiving = ONE pair of braces

// PARENT: passing. One name={value} per prop. Never grouped.
<CustomerTable
  customers={visible}
  sortKey={sortKey}
  onSort={handleSort}
  onSelect={(id) => { setSelectedId(id); }}
/>

// CHILD: receiving. ONE pair of braces inside the parentheses.
export default function CustomerTable({ customers, sortKey, onSort, onSelect }) {
  console.log('table props', customers, sortKey); // first thing to check
  ...
  <tr onClick={() => { onSelect(c.id); }}>
}
  • P1
    Grouped when passing: <Table {customers, sortKey} /> → syntax error pointing at the brace. Fix: customers={customers} sortKey={sortKey}.
  • P2
    No braces when receiving: function Table(customers) → customers.map is not a function (it's the whole props object). Fix: function Table({ customers }).
  • P3
    Two sets of braces: function Table({ customers }, { sortKey }) → sortKey always undefined. Fix: one set: ({ customers, sortKey }).
  • P4
    Received but never passed (or a typo: onselect vs onSelect) → onSelect is not a function on click, or undefined. Fix: the name must match exactly at both ends. Check the parent's JSX.
  • P5
    Using the parent's setter in the child: setSelectedId(id) inside the table → setSelectedId is not defined. The child can't see the parent's variables. Fix: pass a callback (onSelect) and call that.
  • P6
    Calling instead of passing: onClose={setOpen(false)} → "Too many re-renders". Fix: onClose={() => { setOpen(false); }}.
  • P7
    Passing the whole thing when the child needs one piece is fine; passing nothing because "it's in the parent" is not. If the child uses it, it's in the child's braces.
  • P9
    New component looks like it's not there: an empty div has zero height, so it's invisible even though it rendered. A component that returns null or undefined (a stub, if (!open) return null with no open passed, or braces with no return) renders nothing, with no error. Habit: start every new component with visible placeholder text and style={{ background: 'red' }}, plus console.log('X rendered'). Style it properly once you can see it.
  • P8
    New component, nothing shows: forgot to render it in the parent's JSX, or forgot to import it. Check both before anything else.

Error decoder: what it says → what it usually means

  • !
    X is not a function → X isn't what I think. Usually a prop not passed or misnamed (P4), or the props object without braces (P2). Log X.
  • !
    Cannot read properties of undefined (reading 'name') → the thing before .name is undefined. A find found nothing, data hasn't loaded, or a prop is missing. Guard it with if (!x) return null;.
  • !
    X is not defined → X doesn't exist in this file or function. Not imported, or it lives in another component (P5).
  • !
    Unexpected token → a typo in syntax: a brace, paren or comma. Look at the line it names and the line above. In JSX it's often an if or grouped props (P1).
  • !
    Too many re-renders → a setter is being called during render. Find onClick={setX(…)} and wrap it in an arrow (P6).
  • !
    Element type is invalid … got: undefined → bad import. Default export ↔ no braces; named export ↔ braces with the exact name.
  • !
    Objects are not valid as a React child → I put an object in JSX: {customer} instead of {customer.name}, or a groupBy result.
  • !
    Each child in a list should have a unique "key" → add key={item.id} to the outermost tag returned from the map.
  • !
    No error, it just doesn't appear (modal, drawer, new component) → in this order: (1) is {modal} actually in the JSX? (2) console.log('open', open): does it flip to true on click? Flips back immediately → a backdrop/outside-click handler or a form submit is closing it. (3) Red-box test: style={{ background: 'red', padding: 40 }}. Red shows → CSS problem. (4) In DevTools, the preview is in a shadow root / iframe, so search won't find it. Trust the console log instead.
  • !
    No error, wrong screen → the logic runs on the wrong value. console.log the input and output of the step right before it (filter, sort, find).

When it breaks and I'm panicking (2 minutes, not 10)

  • 1
    Say it out loud: "Something's off in the wiring. Let me check what the child is actually getting."
  • 2
    Log the props on the first line of the child. A whole object or undefined → wiring problem (P1–P5), not logic.
  • 3
    Shrink to one prop. Pass only the list. Once it renders, add the next prop. Test after each one.
  • 4
    Still stuck → Ctrl+Z back to the last working state and add one thing at a time. That's a professional move, not a failure.
  • 5
    Prevention: change one thing, see it work, then the next. Never type five things and then test.

Data: words → tool → what comes back

  • →
    "search / filter / tabs" → filter → array (maybe empty)
  • →
    "newest first / A–Z" → [...arr].sort → array
  • →
    "show as / just the names" → map → array, same length
  • →
    "the selected one" → find → one item or undefined
  • →
    "3 unread / X of Y" → filter().length → number. "total" → reduce(…, 0)
  • →
    "any / all" → some / every → true/false
  • →
    "grouped under" → Object.groupBy → OBJECT (no .map!) → Object.entries or loop over an ORDER array
  • →
    "per status counts" → reduce(…, {}) → object. "unique teams" → [...new Set(arr)] → array
  • →
    "author name from users" → Object.fromEntries(users.map(u => [u.id, u])) → lookup object, then map
  • !
    Arrays are for showing, objects are for looking up. Order: filter → sort → group → render. Grouped list = map inside a map.

state = what the user controls; everything else derived

const [query, setQuery] = useState('');
const [team, setTeam] = useState('All');

// derived: plain values, recalculated each render

const teams = ['All', ...new Set(people.map((p) => p.team))];

Select by id + lift state

state in the common parent; children call callbacks

function App() {
  const [items, setItems] = useState(INITIAL);
  const [selectedId, setSelectedId] = useState(null);
  const selected = items.find((i) => i.id === selectedId);   // derived, never a copy

  return (
    <>
      <List items={items} selectedId={selectedId} onSelect={setSelectedId} />
      <Detail item={selected} />
    </>
  );
}

function List({ items, selectedId, onSelect }) {
  return items.map((i) => (
    <button key={i.id} className={i.id === selectedId ? 'row is-active' : 'row'} onClick={() => onSelect(i.id)}>
      {i.title}
    </button>
  ));
}

function Detail({ item }) {
  if (!item) return <p>Select something.</p>;
  return <h2>{item.title}</h2>;
}

Form with validation + async submit

preventDefault, error state, try/catch/finally

const [email, setEmail] = useState('');
const [error, setError] = useState('');
const [submitting, setSubmitting] = useState(false);

async function handleSubmit(e) {
  e.preventDefault();
  const value = email.trim();
  if (!value.includes('@')) { setError('Enter a valid email address.'); return; }
  setSubmitting(true);
  try {
    const result = await invite(value);
    onInvited(result);
    setEmail('');
  } catch (err) {
    setError(err.message);
  } finally {
    setSubmitting(false);
  }
}

<form onSubmit={handleSubmit} noValidate>
  <input
    className={error ? 'input has-error' : 'input'}
    value={email}
    onChange={(e) => { setEmail(e.target.value); setError(''); }}
  />
  {error && <p className="error">{error}</p>}
  <button type="submit" disabled={submitting}>{submitting ? 'Saving…' : 'Save'}</button>
  <button type="button" onClick={onCancel}>Cancel</button>
</form>

Fetch with the cancelled flag

loading / error / empty / success, refetch, retry

const [status, setStatus] = useState('loading');   // 'loading' | 'error' | 'success'
const [data, setData] = useState([]);
const [error, setError] = useState('');
const [attempt, setAttempt] = useState(0);          // bump to retry

useEffect(() => {
  let cancelled = false;
  setStatus('loading');
  getOrders(range)                                  // the codebase's API function
    .then((result) => {
      if (cancelled) return;                        // a newer request replaced this one
      setData(result);
      setStatus('success');
    })
    .catch((err) => {
      if (cancelled) return;
      setError(err.message);
      setStatus('error');
    });
  return () => { cancelled = true; };               // runs before the next fetch and on unmount
}, [range, attempt]);                               // refetch when these change

if (status === 'loading') return <p>Loading…</p>;
if (status === 'error') return <div>{error} <button onClick={() => setAttempt((n) => n + 1)}>Try again</button></div>;
if (data.length === 0) return <p>Nothing here yet.</p>;
return <ul>{data.map((d) => <li key={d.id}>{d.name}</li>)}</ul>;

Real fetch: const ctrl = new AbortController(); fetch(url, { signal: ctrl.signal }), check res.ok, ignore err.name === 'AbortError', cleanup ctrl.abort(). Say: "The flag stops a slow old response from overwriting newer data."

Shaping data

sort, group, count, format

[...items].sort((a, b) => a.name.localeCompare(b.name));                // A→Z
[...items].sort((a, b) => b.amount - a.amount);                          // biggest first
[...items].sort((a, b) => new Date(b.updatedAt) - new Date(a.updatedAt)); // newest first

const total = items.reduce((sum, i) => sum + i.amount, 0);
const unread = items.filter((i) => !i.read).length;
const anyDone = items.some((i) => i.done);

const sections = ORDER

Escape, click outside, focus

listeners on document need cleanup

const menuRef = useRef(null);

useEffect(() => {
  if (!open) return;
  const onDown = (e) => { if (menuRef.current && !menuRef.current.contains(e.target)) setOpen(false); };
  const onKey = (e) => { if (e.key === 'Escape') setOpen(false); };
  document.addEventListener('mousedown', onDown);
  document.addEventListener('keydown', onKey);
  return () => {
    document.removeEventListener('mousedown', onDown);
    document.removeEventListener('keydown', onKey);
  };
}, [open]);

<div ref={menuRef} className="menu-wrap"> ... </div>

// focus an input when it appears
const inputRef = useRef(null);
